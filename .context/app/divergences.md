# Divergence ledger

Lelañea owns the `leaf-*` seams, `.context/app/`, `components/app/`,
`prisma/schema/app.prisma`, `app/brand-theme.css`, and any new file it creates.
Everything else arrives from Daybreak (which carries Sunrise through) and merges
on every sync.

**A row here is the price of editing one of those files.** Without it, the next
sync meets the change as a conflict with no explanation, and the tempting
resolution — take upstream — silently reverts a decision somebody made on
purpose. So: every edit to a file we do not own gets a row, in the same PR as
the edit (`sunrise.divergences`).

**Filling a seam is not a divergence.** `lib/app/leaf-*.ts`,
`lib/app/reserved-tiers.ts`, `app/brand-theme.css` and the rest of the empty
`lib/app/*` scaffolds exist precisely to be filled, and they merge cleanly.
Only files an upstream tier owns _and keeps evolving_ belong here.

**Every row carries a deletion trigger** — the specific thing that would make it
removable. A ledger without them only grows.

## How to use this on a sync

Read the rows before you merge, not after. For each conflict in a file named
here, the "on conflict" column says what to do; the default is to re-apply our
change on top of upstream's, never to take one side wholesale.

## Row 1 · `app/layout.tsx` — brand fonts on `<html>`

|                      |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **File**             | `app/layout.tsx` (Sunrise)                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Change**           | Imports `brandFontVariables` from `app/fonts.ts` and adds it as `className` on `<html>`.                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Forced by**        | `next/font` returns a class that must be applied to a real element; there is no seam that applies one. `lib/app/` is out — the platform's own ESLint boundary bans runtime `next/*` imports there and names `app/` as the remedy. A route-group layout would miss body-portaled overlays (`.context/ui/surface-theming.md` constraint 1), leaving every dialog and toast in the browser's default face.                                                                                        |
| **On conflict**      | Keep both. Take upstream's `<html>` attributes and re-add `className={brandFontVariables}`. If upstream has introduced its own `className` there, compose rather than replace.                                                                                                                                                                                                                                                                                                                 |
| **Upstream status**  | Not filed. This is ordinary fork work that a seam would tidy, not a defect. Known cost: `next/font` defaults to `preload: true`, so all seven woff2 files are preloaded (Instrument Serif normal + italic, Hanken Grotesk 400/500/600, Cormorant Garamond italic 400 + 500) on `/admin` too, where `brand-theme.css` never maps them onto a font token. Accepted — `preload: false` would delay the faces on the surfaces that DO use them, to save bandwidth on an internal, low-traffic one. |
| **Deletion trigger** | Daybreak or Sunrise ships a font seam — any scaffold whose value the root layout applies to `<html>`. Move the three loaders into it and delete this row.                                                                                                                                                                                                                                                                                                                                      |

## Row 2 · `app/layout.tsx` + `hooks/use-theme.tsx` — the system preference stays a default

|                      |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Files**            | `app/layout.tsx` (the no-flash script) and `hooks/use-theme.tsx` — both Sunrise                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Change**           | Both stop writing the resolved system preference to `localStorage`. The hook now also follows `prefers-color-scheme` changes for as long as nothing is stored. Only `setTheme` writes. The storage key, the `<html>` class and the hook's public shape are untouched.                                                                                                                                                                                                                    |
| **Forced by**        | Upstream persisted the _default_ as though it were a choice, so from the second visit onward "hasn't chosen" and "chose light" were the same stored state, and a later OS switch was never followed. Decision D4 (owner, 8 September 2026) is that the system preference is the default and only the toggle persists. In vanilla Sunrise the bug is invisible — both themes are near-greyscale; against Lelañea's oyster white and near-black charcoal it is the whole first impression. |
| **On conflict**      | Keep ours. The two files must agree: the script's resolution and the hook's initial state are the same expression, and if they diverge the first paint disagrees with the first render. If upstream has rewritten theme handling entirely, check whether it now distinguishes "no choice" from an explicit one — if it does, take upstream and delete this row.                                                                                                                          |
| **Upstream status**  | Filed: [daybreak#236](https://github.com/human-centric-engineering/daybreak/issues/236). Reported as a defect with this repo as the reference implementation; we did not volunteer the platform's fix (`B7`). Daybreak may fix it at its own tier or hand it to Sunrise — either closes this row.                                                                                                                                                                                        |
| **Deletion trigger** | daybreak#236 lands: theme resolution that treats an absent `localStorage` value as "follow the system" rather than writing to it, whether as a fix or behind a seam. Then both edits revert to upstream. Check on the sync that carries it, not before — a partial fix moving only the hook still needs our layout-script change.                                                                                                                                                        |

## Row 3 · `components/surface-sync.tsx` — the surface must swap before paint

|                      |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **File**             | `components/surface-sync.tsx` (Sunrise)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Change**           | `useEffect` → a guarded `useIsomorphicLayoutEffect`, so `data-surface` is rewritten before the browser paints. One added import, one changed hook; the effect body is untouched.                                                                                                                                                                                                                                                                                                                                                                                 |
| **Forced by**        | `useEffect` runs after paint, so a client-side navigation between two differently-themed surfaces shows one frame of the old theme. Upstream is right that this is harmless in vanilla Sunrise — an empty `brand-theme.css` means no theme delta — but we are the fork that filled it, and `components/auth/user-button.tsx` puts a `<Link href="/admin">` in the site header (via `components/layouts/header-actions.tsx`). So an admin moving between the app and `/admin` sees a full frame of oyster white over the admin's white, and charcoal coming back. |
| **On conflict**      | Keep ours, unless upstream has itself moved to a layout effect — in which case take upstream. This is upstream's own documented remedy, not an invention, so a conflict most likely means the file was restructured rather than that the advice changed.                                                                                                                                                                                                                                                                                                         |
| **Upstream status**  | Not filed as a defect: upstream's comment already describes this exact case and names this exact fix, so there is nothing to report. It is a fork switch that Sunrise anticipated.                                                                                                                                                                                                                                                                                                                                                                               |
| **Deletion trigger** | Sunrise makes the layout effect the default, or ships the timing as a prop/seam. Also removable if `classifySurface` ever collapses to a single surface here, since the delta is what makes the frame visible.                                                                                                                                                                                                                                                                                                                                                   |

## Row 4 · `scripts/ci/scoped-tests.ts` — a leaf entry in `ALWAYS_RUN_TESTS`

|                      |                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **File**             | `scripts/ci/scoped-tests.ts` (Sunrise)                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Change**           | One entry appended to `ALWAYS_RUN_TESTS`: `tests/unit/components/app/ui/tokens-only.test.ts`. Nothing else in the file is touched.                                                                                                                                                                                                                                                                                                                        |
| **Forced by**        | That test's two inputs are files rather than modules — a new component carrying a colour literal, and a token deleted from `app/brand-theme.css` that a component still names — so no import chain reaches it. A branch touching only the stylesheet would not select it, which is precisely the branch on which a token disappears out from under its consumer. `npm run test:changed` flags the file itself as undeclared, which is how this was found. |
| **On conflict**      | Keep both, in either order. The array is unordered and the file's own header says upstream removes no entries, so a conflict here is two appends landing at the same place and not a disagreement. Take upstream's new entries and re-add ours beneath them.                                                                                                                                                                                              |
| **Upstream status**  | Not filed, and nothing to file. The file's header names appending as the fork path in as many words: "A fork adding its own whole-tree invariant appends to this list." This row exists for the merge mechanics, not because anything is wrong.                                                                                                                                                                                                           |
| **Deletion trigger** | The guard stops being whole-tree — either `tokens-only.test.ts` is deleted, or `components/app/ui/` gains a lint rule that catches a colour literal at the file that declares it, at which point the test's input becomes the module graph again and the entry is dead weight.                                                                                                                                                                            |

## Row 5 · `tests/unit/components/layouts/protected-nav.test.tsx` — pinned to our nav

|                      |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **File**             | `tests/unit/components/layouts/protected-nav.test.tsx` (Sunrise — blob identical on `sunrise/main` and `daybreak/main` at `4ed01375` before this change)                                                                                                                                                                                                                                                                                                                                       |
| **Change**           | One case. `renders the platform default links when no override is set` → `renders this fork's nav from the filled seam`: asserts `/app` "Your journey" in place of `/dashboard` "Dashboard", keeps the `/profile` and `/settings` assertions untouched, and adds one asserting no `/dashboard` link survives. The other six cases are unchanged.                                                                                                                                               |
| **Forced by**        | `HB2`, one tier down. The case reads `lib/app/protected-nav.ts` unmocked and asserts the platform default; §04 t-9 fills that seam, so it necessarily fails. Pinned rather than deleted because what it really protects is the component's end of the seam — that `ProtectedNav` reads the list, renders every entry and gets the hrefs right — and that is worth keeping whatever the values are. The generic replacement mechanism stays covered by the case below it, which mocks the seam. |
| **On conflict**      | Keep ours, and re-read it. A conflict most likely means upstream changed `DEFAULT_PROTECTED_NAV` — which does not affect us, since we replace it wholesale — or restructured the file. If upstream has since given the case a way to run against a filled seam (a fixture, or mocking the seam as the third case already does), take upstream and delete this row: that is strictly better than pinning.                                                                                       |
| **Upstream status**  | Not filed, and nothing to file. This is the documented consequence of filling a seam, and `defaults.test.ts` says so in its own header. Worth noting for the tier above, though: `defaults.test.ts` is _designed_ to be pinned by a fork and says so, while this file asserts the same default with no such note — so a fork meets it as a surprise. If it recurs on another seam, that is worth raising as a docs gap rather than a defect.                                                   |
| **Deletion trigger** | We stop replacing the platform nav — either `lib/app/protected-nav.ts` returns to `null`, or upstream drops `/dashboard` from `DEFAULT_PROTECTED_NAV` so the default and our value agree. Also removable if upstream reworks the case to mock the seam.                                                                                                                                                                                                                                        |
