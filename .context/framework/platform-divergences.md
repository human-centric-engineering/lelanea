# Platform divergences — Daybreak's edits to Sunrise's files

Every edit Daybreak carries to a file Sunrise owns, one row each. **Read this
before resolving any conflict in a Sunrise sync.** The sync order, and what each
column means, are in [`CUSTOMIZATION.md` §9](../../CUSTOMIZATION.md#the-divergence-ledger).

This is the file-level record: what to do when a file conflicts.
[`upstream-asks.md`](./upstream-asks.md) sits beside it and tracks the seam work:
what Daybreak has asked Sunrise for, including asks that touch no Sunrise file.
Where a row here has an ask there, the issue number joins them.

A leaf built on Daybreak keeps its own ledger at `.context/app/platform-divergences.md`
and does not write this one.

## Left out

Three kinds of Daybreak edit are deliberately not rows:

- **The `lib/app/*` bridges** (roster in the [`CLAUDE.md`](../../CLAUDE.md) banner)
  and `lib/app/reserved-tiers.ts`, where `CUSTOMIZATION.md` tells a fork to add its
  tier. Sunrise ships them to be filled. On a conflict in `reserved-tiers.ts`, keep
  the `DAYBREAK` block.
- **Daybreak's identity:** `package.json`, `README.md`, `.env*` and the
  `CLAUDE.md` banner and Hub bootstrap block.
- **`CUSTOMIZATION.md`**, which the banner also lists as Daybreak's. It conflicts
  on most syncs all the same. In the §4 seam table, keep each `lib/app/leaf-*` row
  under its bridge and add upstream's new rows. In §9, keep "Before your first
  sync" ahead of upstream's steps.
